# Football Analytics — local coaching workspace

## Approved direction
An interactive coaching workspace running locally on this Mac Intel, with annotated video export. Start with the existing 75-second Persibo clip, not a whole match. The user approved a video workspace, possession rings, passing lines, event timeline, corrections, and briefing export.

- Source: `/Users/aaa/Downloads/Gol_1_Persibo_Sehabudin.mp4`
- Initial detections: `/Users/aaa/Downloads/tracking_Gol_1_Persibo_Sehabudin.csv`

- Python environment: `/Users/aaa/Downloads/.football-analyzer-py311/`

The existing ball observations cover only 87 of 1,125 processed frames in clip one. These are observations, not validated ground truth. Do not automatically infer possession or completed passes across long missing-ball intervals. Tracker IDs are not player shirt numbers or stable identities across camera cuts.

## Workspace
Video is the primary view. A synchronized overlay renders selected-player rings, ball observations, and confirmed passing lines. A right-hand inspector displays event details and correction controls. A bottom timeline lists events and seeks the player to their timestamps.

Two workflows:
1. Review AI observations and explicitly confirm or correct events.
2. Add a manual event by seeking to release and reception, then clicking positions in the video.

Manual corrections persist locally and remain separate from model observations. A source badge distinguishes imported detections, AI suggestions, and coach-confirmed events.

## Data contracts
Observations: timestamp seconds, frame, entity type, local tracker ID, team cluster, source-video pixel position. Team clusters have neutral labels until a coach assigns actual teams.

Pass events: unique ID, start/end seconds, source/target positions, optional player references, outcome (`completed`, `intercepted`, `out`, `unknown`), provenance, review status, note. Possession intervals: start/end seconds, player track reference or manual anchor, provenance.

No metres, speed, acceleration, or tactical quality score without calibration and validation. Unknown outcomes are excluded from completion-rate denominators; display unknown and unreviewed counts separately.

## Export
Render overlays onto the original video at its original timing, preserve available audio, produce browser/QuickTime-compatible H.264 MP4. Use the same normalized coordinates and event-time definitions in browser and export. Show job progress and actionable errors.

## Architecture
A loopback-only Python service owns media, imported observations, a SQLite project database, and background export jobs. A browser frontend owns playback and SVG overlays. FFmpeg handles final encoding/audio; OpenCV handles annotation frames. The existing Python environment supplies CV dependencies.

## Validation
Verify timestamp/frame mapping, letterboxed pointer coordinates, event persistence, unknown-event handling, and export overlay/audio alignment. Visually review the first clip at release/reception and a camera cut. Successful file generation is not proof of tracking accuracy.

## Delivery stages
1. Local review workspace using existing media/CSV.
2. Possession and pass corrections with persistence.
3. Annotated export and checks against browser preview.
4. Improve ball detection and calibrated tracking after the review workflow works.
